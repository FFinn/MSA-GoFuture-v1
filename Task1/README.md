# Task1. Проектируем домены

В этом задании зафиксирован поэтапный переход GoFuture от монолита к восьми доменным сервисам, соответствующим продуктовым командам.

## Артефакты

- [`ADR-001-domain-decomposition.md`](./ADR-001-domain-decomposition.md) — нефункциональные требования, карта доменов, очерёдность выделения сервисов, механизм обратной совместимости, план миграции данных, альтернативы и риски.
- [`C2-to-be.puml`](./C2-to-be.puml) — целевая диаграмма C2 на период декомпозиции с доменными сервисами, отдельными хранилищами, шлюзом программного интерфейса, ACL и временно сохраняемым монолитом.

## Ключевые решения

Декомпозиция выполняется постепенно, без общей остановки платформы. Внешние клиенты продолжают работать через единую входную точку. Шлюз программного интерфейса и ACL направляют уже перенесённые операции в доменные сервисы, а оставшиеся — в монолит.

У каждого выделенного сервиса появляется собственное хранилище и право владения своими данными. Прямые обращения к базам других сервисов запрещаются. Для переноса больших объёмов используется первоначальная пакетная загрузка, затем захват изменений данных и поэтапное переключение трафика после сверки.

Порядок выделения: Notification → Geography → Pricing и Analytics → Driver → Booking → Fraud → Payments. Финансовый домен переносится последним из-за максимальной цены ошибки и необходимости строгой сверки операций.
