# Мониторинг событийной платформы GoFuture

Документ дополняет [`ADR-002-event-driven-architecture.md`](./ADR-002-event-driven-architecture.md) и описывает, какие показатели собираются для событийной платформы и какими средствами они контролируются.

## 1. Подход

Для прикладных сервисов используется метод **RED**:

- **Rate** — скорость обработки запросов и событий;
- **Errors** — количество и доля ошибок;
- **Duration** — длительность обработки.

Для Kafka и Flink этого недостаточно. Платформа может оставаться формально доступной, но накапливать отставание. Поэтому дополнительно контролируются:

- состояние брокеров и репликации Kafka;
- отставание групп потребителей;
- возраст самого старого необработанного события;
- состояние заданий Flink и контрольных точек;
- обратное давление потоковых операторов;
- доставка из транзакционного исходящего журнала в Kafka;
- состояние Saga и сроки выполнения её шагов.

Метрики рассматриваются отдельно по регионам, чтобы нормальная работа одного региона не скрывала деградацию другого.

## 2. Инструменты

| Инструмент | Назначение |
|---|---|
| **Prometheus** | Сбор числовых метрик сервисов и платформы |
| **Grafana** | Панели по регионам, доменам, Kafka, Flink и Saga |
| **Alertmanager** | Маршрутизация оповещений |
| **Loki** | Централизованные журналы сервисов и платформы |
| **Kafka Exporter** | Отставание групп потребителей и состояние топиков |
| **JMX Exporter** | Метрики брокеров Kafka и Kafka Connect |
| **Flink Prometheus Reporter** | Метрики потоковых заданий Flink |
| **PostgreSQL Exporter** | Метрики доменных баз PostgreSQL |
| **OpenTelemetry Collector** | Сбор распределённых трасс |
| **Jaeger** | Хранение и просмотр распределённых трасс |

Все инструменты отражены на [`C2-event-platform.puml`](./C2-event-platform.puml). Все доменные сервисы передают журналы в Loki и трассы в OpenTelemetry Collector.

## 3. Метрики Kafka

### Брокеры

- скорость поступления и выдачи сообщений;
- входящий и исходящий сетевой поток;
- использование диска;
- количество недоступных партиций;
- количество партиций с неполным числом синхронных реплик;
- изменения состава ISR;
- длительность обработки запросов чтения и записи;
- число активных брокеров.

### Группы потребителей

- текущее отставание в сообщениях;
- отставание во времени;
- максимальное отставание по одной партиции;
- скорость роста или уменьшения отставания;
- количество активных потребителей;
- количество перебалансировок;
- скорость обработки сообщений.

Для `driver.location` и потоков ценообразования допустимое отставание должно быть ниже, чем для аналитических потребителей. Числовые пороги определяются нагрузочными испытаниями.

## 4. Метрики Flink

Для каждого задания контролируются:

- состояние задания;
- количество входящих и исходящих записей;
- число обработанных записей в секунду;
- обратное давление;
- длительность контрольной точки;
- количество успешных и неуспешных контрольных точек;
- время с последней успешной контрольной точки;
- количество перезапусков;
- размер состояния;
- отставание водяного знака от текущего времени;
- число ошибочных записей.

Отдельная панель показывает путь `DriverLocationUpdated → DemandSupplySignalCalculated → DynamicPriceUpdated`, чтобы видеть фактическую задержку расчёта динамической цены.

## 5. Метрики доставки из исходящего журнала в Kafka

Для каждого доменного сервиса контролируются:

- количество записей `outbox`, ещё не опубликованных в Kafka;
- возраст самой старой непереданной записи;
- скорость появления записей `outbox`;
- скорость публикации Debezium;
- состояние Kafka Connect;
- отставание захвата изменений данных;
- количество ошибок публикации;
- количество сообщений, отправленных на повторную обработку или в топик недоставленных сообщений.

Рост возраста самой старой записи `outbox` означает, что другие домены начинают получать устаревшее состояние, даже если сам сервис продолжает отвечать на запросы.

## 6. Метрики потребителей

- скорость получения и успешной обработки событий;
- длительность обработки p50/p95/p99;
- количество ошибок по типам;
- число повторных попыток;
- число сообщений в топике недоставленных сообщений;
- число повторов, отфильтрованных реестром обработанных событий;
- возраст самого старого ожидающего события;
- количество ошибок несовместимой схемы.

Сообщения Booking и Payments в топике недоставленных сообщений требуют отдельного разбора, поскольку могут означать незавершённую поездку или финансовую операцию.

## 7. Метрики Saga

- число активных Saga;
- число новых, успешно завершённых, отменённых и ошибочных Saga;
- длительность Saga p50/p95/p99;
- длительность каждого шага;
- число превышений срока на каждом шаге;
- количество компенсаций;
- количество Saga без изменения состояния дольше установленного срока;
- время от `BookingCreated` до `BookingConfirmed`;
- время поиска и резервирования водителя;
- время авторизации платежа;
- число повторных команд, остановленных идемпотентностью.

Из агрегированной метрики в Grafana должна быть возможность перейти к конкретному `saga_id`, затем к журналам в Loki и трассе в Jaeger.

## 8. Бизнес-метрики реального времени

- количество создаваемых заказов по регионам и зонам;
- количество активных поездок;
- количество доступных водителей;
- отношение спроса к предложению по зоне;
- медианное и p95 время назначения водителя;
- доля заказов, где водитель не найден до истечения срока;
- текущий динамический коэффициент по зонам;
- частота пересчёта динамической цены;
- количество рекомендаций по перераспределению водителей;
- доля отклонений Fraud;
- доля неуспешных авторизаций и списаний.

## 9. Основные оповещения

| Сигнал | Условие | Ответственная команда |
|---|---|---|
| Недоступная партиция Kafka | Есть хотя бы одна недоступная партиция критичного топика | SRE-команда |
| Неполная репликация | Состояние сохраняется дольше допустимого периода | SRE-команда |
| Рост отставания критичного потребителя | Превышено допустимое время доставки | SRE-команда и владелец потребителя |
| Исходящий журнал не выгружается | Возраст старейшей записи растёт | Команда домена и платформенная команда |
| Kafka Connect/Debezium остановлен | Соединитель не работает | Платформенная команда |
| Задание Flink остановлено | Задание не выполняется | Инженеры данных и SRE-команда |
| Ошибки контрольных точек Flink | Несколько последовательных ошибок | Инженеры данных и SRE-команда |
| Появилось сообщение Booking/Payments в топике недоставленных сообщений | Новое сообщение | Владелец домена |
| Saga не меняет состояние | Превышен срок шага | Booking и SRE-команда |
| Резко выросло число компенсаций | Отклонение от обычного уровня | Booking и зависимый домен |

Числовые пороги определяются по результатам нагрузочных испытаний и затем привязываются к целевым показателям доступности и времени реакции системы.

## 10. Панели Grafana

1. **Обзор событийной платформы** — регионы, брокеры, входящий поток, недоступные партиции и топики недоставленных сообщений.
2. **Потребители Kafka** — отставание по группам, топикам и регионам.
3. **Flink в реальном времени** — состояние заданий, обратное давление, контрольные точки и задержка вычислений.
4. **Saga поездки** — активные процессы, длительность, ошибки, компенсации и зависшие Saga.
5. **Доставка событий** — исходящий журнал, Debezium, Kafka Connect, повторы и топики недоставленных сообщений.
