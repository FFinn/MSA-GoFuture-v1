# Task2. Проектируем событийно-ориентированную архитектуру

В этом задании спроектирована событийная платформа GoFuture для обработки более 500 тысяч одновременно выполняемых поездок, динамического ценообразования и потоковой обработки данных в реальном времени.

## Артефакты

- [`ADR-002-event-driven-architecture.md`](./ADR-002-event-driven-architecture.md) — модель доменных событий, схема топиков Kafka, региональное разделение, Apache Flink, Saga поездки, механизмы надёжной доставки, альтернативы и риски.
- [`C2-event-platform.puml`](./C2-event-platform.puml) — диаграмма C2 событийной платформы с Kafka, Flink, Debezium, доменными сервисами и средствами наблюдаемости.
- [`monitoring.md`](./monitoring.md) — подход к мониторингу, список инструментов, метрики Kafka/Flink/Outbox/Saga и основные оповещения.

## Ключевые решения

Доменные события передаются через Apache Kafka. Для региональной изоляции используется отдельное пространство топиков вида `gofuture.<region>...`, а внутри региона события распределяются по нескольким партициям по ключу агрегата (`booking_id`, `driver_id`, `payment_id`, `zone_id`). Это позволяет сохранять порядок событий одного агрегата, не превращая весь регион в одну последовательную очередь.

Для вычислений над непрерывным потоком выбран Apache Flink. Он рассчитывает спрос и предложение по зонам, формирует сигналы динамического ценообразования, рекомендации по перераспределению водителей и потоковые признаки для Fraud.

Процесс поездки реализуется как оркестрационная Saga с итоговой согласованностью. Состояние Saga принадлежит Booking. Расчёт цены и проверка Fraud выполняются параллельно, далее координируются поиск водителя, авторизация платежа, выполнение поездки и окончательное списание.

Надёжная публикация доменных событий строится на Transactional Outbox + Kafka Connect/Debezium. Потребители используют Inbox и идемпотентную обработку. Сквозная гарантия формулируется как «доставка не менее одного раза + идемпотентность», без ложного обещания exactly-once для внешних платежных операций.

Мониторинг построен на существующем стеке Prometheus, Grafana, Alertmanager и Loki с добавлением Kafka/JMX Exporter, Flink Prometheus Reporter, OpenTelemetry и Jaeger.
